# AKNOI

一个由种子生成的六题同步刚性块游戏。

## 规则

- 一次方向操作同时作用于所有未提交题目。
- 每题随机生成若干子任务；不同形状代表不同子任务，分值随题目变化。
  - `D1T1`、`D2T1` 是签到题，只有三档：`1×1`、一个中间形状、100 分的 `2×2`。
  - 其余四题各五档：`1×1`、三个中间形状、100 分的 `3×3`。
- 题头的子任务清单按分值从低到高排序，并同时显示分值与形状。
- Verdict 升级链：`CE → RE → UKE → MLE → TLE → WA → AC`。
- 块分数为“子任务分值 × Verdict 系数”：
  - CE、RE：0
  - UKE：×0.1
  - MLE：×0.2
  - TLE：×0.4
  - WA：×0.8
  - AC：×1
- 每题分数是区域内所有块的当前最高分，不保留历史峰值。
- 上机满分 600（六题 × 100）。对外显示的总分还要加上 **笔试 105 分**，满分 705；
  单题分数和单块分数不加，存档与服务端校验用的也一律是上机分。
- `1×1` 的 O2 块撞入普通目标时直接使目标 Verdict 升一级；AC 无法与 O2 结合。
- 六道题依次为 `D1T1`、`D1T2`、`D1T3`、`D2T1`、`D2T2`、`D2T3`。
- 可以随时手动提交任意题目；提交后锁定当时分数，不再受方向操作影响。
- 没有自动提交：题目塞满或锁死后只是无法再移动，仍需自己按提交结算。

## 碰撞

每次操作按移动方向从前到后结算。每个块一次移动到最终位置：

1. 前方块先贴边或停在障碍前。
2. 后方块再向前移动。
3. 普通块只有 Verdict 相同、仅接触一个目标，并且前方块完整覆盖移动块的截面时才能合并：横向看完整高度，纵向看完整宽度。
4. O2 是例外：作为移动块撞入非 AC 普通目标时，不要求 Verdict 相同，直接将目标升一级。
5. 合并后前方块保留子任务形状，每次操作最多合并一次。

## 游戏种子与存档

题目子任务、子任务分值、初始布局、后续生成及所有概率（包括 O2 生成）均来自同一个游戏种子。相同种子加相同操作序列会得到相同比赛。

因为引擎完全确定，存档只需记录 **种子 + 操作序列**（每步的移动方向、每次提交的题目），不保存任何棋盘状态：

- 每次成功操作后写入 `localStorage` 的 `aknoi-save-v1`。
- 重新打开页面时用 `replayGame(seed, actions)` 重放推算出当前局面，继续游戏。
- URL 中带 `#种子` 时以该种子开新局；点「重开」或「新种子」会清空存档。
- 存档损坏、被手改或来自旧版本时会被安全丢弃，回退到新开一局。

## GitHub Pages

仓库已包含 `.github/workflows/deploy-pages.yml`。在 GitHub 仓库的 **Settings → Pages** 中将 Source 设为 **GitHub Actions**；之后推送到 `main` 会自动测试、构建并部署。Vite 使用相对资源路径，因此项目页和自定义域名都可直接运行。

```bash
npm install
npm test
npm run build
npm run dev
```

## 排行榜（周榜 + 总榜）

排行榜是独立部署的 PHP 站点（`server/` 目录），不随 GitHub Pages 发布。

- **周榜**（`index.php`）：只统计本周的成绩，每周一 00:00 换榜（时区由 `server/config.php` 的 `timezone` 决定，默认 `Asia/Shanghai`）；并且**只统计本周种子** —— 种子由 `weekly_seed` 配置指定，留空时自动按 ISO 周生成（形如 `AKNOI-2026-W33`，每周一自动换新）。上一周的数据会被自动清掉，榜单每周从零开始。
- **总榜**（`alltime.php`）：**不限定种子**，任何种子、任何一周的成绩都算；每个账号只保留一行历史最好成绩。可以按种子筛选查看。
- **账号**：上传成绩前必须先注册/登录（`register.php` / `login.php`），排行榜上的“选手”就是用户名，不再手填名字。密码用 `password_hash` 加盐存储。
- **SQL 只存最好成绩**：周榜表 `aknoi_scores` 每个账号每周最多一行，总榜表 `aknoi_alltime` 每个账号最多一行。上传的分数比已有纪录更高时原地更新那一行，等于或更低直接拒绝——没有“显示全部记录”这种功能了。
- **防作弊不变**：服务端用 `engine.php`（PHP 移植版引擎）完整重放上传的 `.dat` 存档重算分数，和文件里声称的分数对不上就拒绝；同一局（相同种子 + 相同操作）每周只记录一次；上传限流按 IP。

### 部署

1. 把 `server/` 下的文件放进主机的 `htdocs/`，数据库连接放在 `htdocs/db/db.php`（提供 `$db`，至少要有 `query($sql, $params)` 方法并返回可 `fetch()` / `fetchAll()` 的结果对象）。
2. 复制 `server/config.php` 为 `server/config.local.php`，填上 `install_token` 和 `ip_salt`（想手动指定本周种子就再加 `'weekly_seed' => 'xxx'`）。
3. 访问 `install.php?token=你的令牌` 建表。若检测到旧版成绩表，会先改名备份为 `aknoi_scores_legacy_<时间戳>` 再建新表，旧数据不会丢（但不会自动迁移成账号）；已有周榜数据时会把每个账号的最好成绩回填进总榜。
4. 建完表后删除 `install.php`。

`server/engine.php` 与 `src/game/engine.ts` 必须逐位一致，改动时请运行 `npm test`（含 PHP 移植版引擎的差分测试）。
